# Khalil Audit System

## Руководство администратора

Версия документа: X3-dev.3
Назначение: эксплуатация, пользователи, файлы, уведомления и интеграции

### 1. Зона ответственности

Администратор поддерживает доступ к системе, выбирает формат клиентского результата, управляет Telegram, брендированием, матрицей решений, пользователями и CRM. Администратор не меняет программный код и не переносит изменения между репозиториями.

Админка намеренно не показывается заказчику и открывается только по адресу с `?admin=1`.

### 3. Первый запуск

1. Создайте проект Supabase.
2. В SQL Editor выполните миграции `001`, `002`, `003`, `004` из папки `db`.
3. В Streamlit Secrets добавьте `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `ADMIN_USERNAME`, `ADMIN_PASSWORD_HASH`, Telegram и ИИ-ключи.
4. Перезапустите приложение.
5. Откройте админку и войдите начальной учетной записью.
6. Создайте персональные учетные записи и отключите общую учетную запись после проверки.

### 4. Роли пользователей

- Администратор: полный доступ, включая создание и отключение пользователей.
- Редактор: изменяет рабочие настройки, Telegram, файлы и CRM.
- Наблюдатель: видит обзор и журнал, но ничего не меняет.

Для каждого сотрудника создавайте отдельную учетную запись. Не передавайте общий пароль в мессенджерах.

### 5. Вкладка «Результат заказчику»

Выберите один режим:

- Презентация - заказчик получает управленческое заключение.
- Excel - заказчик получает экспертную книгу.
- Презентация + Excel - доступны оба файла.

После изменения сохраните настройки и выполните тестовую генерацию. Sales playbook остается внутренним материалом и не должен показываться заказчику.

### 6. Вкладка Telegram

Можно отдельно включать:

- внутреннюю диагностику;
- краткую карточку лида;
- sales playbook;
- клиентский результат.

Также настраиваются подписи и шаблон сообщения. Доступные подстановки показываются рядом с полем. После изменения отправьте тестовый результат и убедитесь, что сообщения и файлы пришли в правильный чат.

Не включайте техническую диагностику в канал, доступный заказчикам.

### 7. Вкладка «Бренд и шаблоны»

Управляемые файлы:

- логотип сайта;
- шаблон клиентской презентации;
- Excel-матрица решений, производителей и дистрибьюторов.

Порядок замены:

1. Скачайте действующий файл как резервную копию и пример формата.
2. Измените копию, сохранив структуру.
3. Загрузите новый файл.
4. Выполните встроенную проверку.
5. Публикуйте только успешно проверенный файл.
6. Сформируйте тестовый отчет и визуально проверьте результат.

Если управляемый файл недоступен, приложение использует резервную версию из репозитория.

### 8. amoCRM

До настройки получите административные права в amoCRM. Для работы нужны:

- домен аккаунта;
- access token;
- ID воронки;
- ID этапа;
- ID ответственного;
- срок первой задачи.

Порядок:

1. Откройте вкладку CRM и выберите amoCRM.
2. Введите домен без лишнего пути.
3. Вставьте только сам токен, без слова Bearer и без кавычек.
4. Заполните ID воронки, этапа и ответственного.
5. Сохраните настройки.
6. Запустите проверку подключения.
7. Активируйте отправку только после успешного теста.

HTTP 401 означает неверный или истекший токен. HTTP 403 Admin access only означает, что учетной записи не хватает прав администратора.

В X3-dev.3 после успешного формирования аудита система автоматически:

1. Находит или создает компанию по точному наименованию.
2. Находит контакт по рабочему email или телефону либо создает новый.
3. Связывает контакт с компанией и делает его главным контактом сделки.
4. Создает сделку `Автоматический аудит — Название компании` в выбранной воронке и на выбранном этапе.
5. Создает ответственному задачу на первичный контакт.
6. Прикрепляет к сделке презентацию и Sales Playbook.

Повторная обработка того же результата защищена ключом идемпотентности. Вкладка `Журнал` показывает успешные, частичные и ошибочные доставки. Частичный статус обычно означает, что сущности созданы, но amoCRM не приняла одно или несколько вложений; проверьте право интеграции `Доступ к файлам`.

Документация amoCRM API: https://www.amocrm.ru/developers

### 9. Bitrix24

Bitrix24 использует ту же админку, но адаптер подключается после приемки amoCRM. Не создавайте отдельную копию приложения. До появления активной формы Bitrix24 переключатель является информационным.

### 10. Восстановление доступа

1. На экране входа нажмите восстановление пароля.
2. Укажите логин.
3. Одноразовый код придет в настроенный внутренний Telegram-чат.
4. Введите код и задайте новый пароль.

Если Telegram недоступен, владелец системы должен создать новый PBKDF2-хеш и заменить `ADMIN_PASSWORD_HASH` в Streamlit Secrets.

### 11. Ежедневная проверка

1. Открывается ли опросник.
2. Открывается ли админка.
3. Нет ли новых ошибок в журнале.
4. Проходит ли тест Telegram.
5. Не истекли ли токены CRM.
6. Достаточны ли квоты ИИ-провайдеров.

После изменения файлов или настроек обязательно формируйте тестовый результат.

### 12. Безопасность

- Никогда не публикуйте service-role ключ, API-ключи, токены и пароли.
- Не добавляйте secrets в GitHub или документы.
- Выдавайте минимально необходимую роль.
- Отключайте учетную запись сотрудника сразу после ухода или смены обязанностей.
- Не отправляйте JSON-черновики заказчика посторонним: они содержат ответы анкеты и контакты.
- При утечке секрета немедленно отзовите его, создайте новый и обновите Streamlit Secrets.

### 13. Если что-то не работает

- Сайт недоступен: Streamlit Cloud → приложение → Manage app → Logs → Reboot.
- Админка сообщает о хранилище: проверить Supabase URL, secret key и миграции.
- Не приходит Telegram: проверить токен, chat ID, доступ бота и настройки вкладки Telegram.
- Не создается результат: проверить внутреннее уведомление и квоты ИИ.
- Презентация восстанавливается PowerPoint: вернуть прошлый шаблон и сообщить разработчику.
- Не найдены производители: проверить структуру и публикацию матрицы портфеля.
- CRM 401: заменить токен.
- CRM 403: получить права администратора amoCRM.
